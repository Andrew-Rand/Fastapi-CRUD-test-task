Апи представляет собой унифицированный ервис, который предоставляет данные для разных клиентов
Каждый клиент индентифицирует себя с помощью заголовка X-client-ID

Мультиклиентность осуществляется на уровне middleware ClientAccessMiddleware
Middleware не проверяет заголовок для url, указанных в переменной ENDPOINTS_WHITELIST (сейчас дам запросы на openApi)

Каждый запрос проверяется на наличие указанного заголовка, в случае его отсутсвия запрос не будет обработан, клиент получит ошибку
Missing X-Client-ID header

При наличии заголовка, middleware проверяет версию api для данного клиента, а также список разрешённых урлов и методов.
В случае успешной проверки запрос перенаправляется в соответсвующую версию АПИ
В противном случае клиент получает ошибку 
Endpoint not allowed for this client"

Конфигурация разрешенных эндпоинтов лежит в файле settings.py
Для демонстрации конфигурация собрана в виде словаря python. Доступны конфигурации для следующих значений X-client-ID
client_a
client_b

Для коммерческого использования конфигурацию лучше хранить в отдельном JSON файле с сохраненим структуры. 
JSON файл должен быть прочитан один раз при инициализации приложения, конфиг помещён в память
При необходимости подключать или отключать новые версии АПИ необходжимо осуществить редактирование этого файла


Остальная структура проекта в директории app

директория core

Здесь храним
middleware
зависимости
sqlalchemy модели
запросы в базу данных, работающие в контексте асинхронных сессий, оформленные в видел отдельных функция в файлах queries.py
базовые схемы pydantic

директория api
Апи разложены по версиям, v1 и v2 в данный момент
Здесь храним роутеры
pydantic схемы для запросов и ответов АПИ

директория common
здесь лежит файл с общими утилитами
Здесь лежит db (хотя её можно положить и в core)


Локальная разработка и запуск
Создать виртуальное окружение и установить зависимости из файла requirements.txt
Создать файл переменных окружения и установить значения переменных по образцу файла .env_sample

Запуск тестов
Для запуска тестов достаточно воспользоваться командой
pytest

или указать путь к конкретной директории или файлу
pytest app/tests/test_api/test_articles.py

Локальный запуск приложения

Запусть контейнеры с приложением и базой данных с помощью команды 
docker compose up --build


Запусть миграции базы данных. Для этого получить доступ к терминалу контейнера с web приложением с помощью команды
docker exec -it <CONTAINER ID> bash

и в терминале контейнера запустить команду
alembic upgrade head

После этого приложение готово к использованию, пример curl для проверка API

curl --location 'http://127.0.0.1:8000/articles' \
--header 'X-client-ID: client_a' \
--header 'Content-Type: application/json' \
--data '{
    "title": "news3",
    "content": "fsaaaaaaaaaaaaaaaaaaa"
}'
